# Task: Settings page — account deletion

User request: "Create a Setting page that allows user to deactivate their accounts."
Clarified via AskUserQuestion: **permanent delete** (over soft-deactivate / both) —
the app is client-only Firebase with no admin backend, so server-side disabling is
not possible; honest UI wording is "Delete account".

Decisions taken in planning:

- `/settings` page (noindex, not in sitemap) with an auth-status-aware
  `AccountSettings` client component; "Settings" entry added to the user menu.
- Deletion sequence in a new `lib/account.ts`: re-authenticate FIRST (popup), then
  delete all `users/{uid}/palettes` docs (batched, new `deleteAllPalettes` in
  `lib/palette-collection.ts`), then `deleteUser`. Ordering is load-bearing:
  reauth-first means an abandoned popup deletes nothing; data-before-auth because
  Firestore rules orphan the docs once the auth user is gone.
- Type-DELETE confirmation dialog; popup-cancel returns to idle silently.
- No Firestore rules changes; no server surface; auth context left untouched.

## Step 2–3 — Codex plan review & enhancement

Codex (read-only `codex exec`) returned 8 findings (3 blockers, 4 improvements,
1 nit). All integrated into plan v2:

1. **Blocker:** `trackEvent("account_deleted")` fails tsc — `AnalyticsEvent` is a
   closed union → `lib/analytics.ts` added to the modified-files list.
2. **Blocker:** provider mapping was underspecified — Firebase `providerData`
   ids are `google.com`/`twitter.com`/`facebook.com` while `createAuthProvider`
   takes local ids; the repo supports all three providers, not "Google-only" →
   explicit mapping table with google fallback.
3. **Blocker:** no handling for deleteUser failing AFTER palettes were deleted →
   typed `AccountDeletionError` with stages (precondition/reauth/data/auth-delete);
   partial-failure alert copy tells the truth and retry is idempotent.
4. Added `auth/user-cancelled` to the silent user-cancel codes.
5. Dialog non-dismissibility spelled out: `showCloseButton={false}` + root
   `onOpenChange` guard while pending.
6. Settings page must not reuse the home shell's `overflow-hidden` (would clip on
   small viewports) → scrollable `max-w-2xl` column.
7. Test placement fixed (`palette-collection.test.ts` for `deleteAllPalettes`),
   `account.test.ts` must mock analytics + client-only, navbar navigation asserts
   a hoisted `next/navigation` push spy.
8. Dropped unused `DeleteAccountResult` type.
