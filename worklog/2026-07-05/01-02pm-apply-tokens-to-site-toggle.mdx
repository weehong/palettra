# Task: "Apply to site" toggle

User request: add a feature that lets the user toggle applying the current design
tokens (palette + typography) directly to the website itself. User floated AI and
a sandbox as options.

Decisions taken in planning:

- Mechanism: runtime override of the app's flat CSS custom properties on
  `document.documentElement`, fully reversible — this is the "sandbox" (scoped,
  non-destructive, no persistence). Iframe isolation rejected for MVP.
- Mapping from the generator's 11-stop scales to the site's flat shadcn-style
  tokens is deterministic and pure (`lib/site-theme.ts`); AI-assisted mapping is
  explicitly out of scope but the `SiteThemeVars` contract allows a later swap-in.
- Scheme-aware (light/dark via `matchMedia`), WCAG-AA-guarded foreground picks.

## Step 2–3 — Codex plan review & enhancement

Codex (read-only `codex exec`) reviewed `task_plan.md` against the codebase and
returned 13 findings. All were integrated into plan v2:

1. **Blocker:** `Palette` carries no role identity → mapper signature changed to
   accept effective `roles: ColorRole[]` (index-aligned with `palettes`).
2. Stale-var risk on changing token sets → hook now diffs applied keys on every
   re-apply, not only on OFF/unmount.
3. Exact restore → snapshot pre-existing inline values (`value`+`priority`) and
   restore them, not blanket `removeProperty`.
4. Dark-mode edges → guard missing `matchMedia`, mock it in jsdom, clean listeners;
   dark `--primary-hover` must be lighter (primary-400); `--overlay` has no dark
   override in globals.css so it is emitted in both schemes.
5. `--overlay` must be opaque (dialogs use `bg-overlay/50` modifiers).
6. Contrast trap: neutral-500 on neutral-50 ≈ 3.4:1 → `--muted` is picked
   programmatically as darkest stop ≥ 4.5:1 vs surface; AA validation for all pairs.
7. "Accent" defined: tertiary preset → role named "accent" → secondary/primary fallback.
8. Stitch wrapper vars beat `:root` inside generator subtree → documented exception.
9. Fonts: `FontPreviewLoader` already loads all curated families; real work is
   `fontStack()` from `lib/fonts.ts`; default-typography apply legitimately swaps font.
10. Runtime Google CSS on chrome = deliberate session-only perf/privacy tradeoff, noted.
11. `"use client"` on the new hook module.
12. Gates corrected: `test:unit:run` (not watch-mode `test:unit`), `npx tsc --noEmit`
    (no typecheck script), lint, build.
13. Test-plan gaps folded into Step D (matchMedia missing, scheme flip while ON,
    role removal while ON, pre-existing inline var preservation, unmount cleanup).

## Step 4 — Implementation (Codex)

Codex implemented plan v2 end-to-end:

- `lib/site-theme.ts` — pure `siteThemeVars({roles, palettes, typography, scheme})`
  mapper: role resolution (primary/neutral/secondary/tertiary-as-accent/error) with
  fallbacks incl. a desaturated neutral ramp derived from primary; light/dark stop
  tables; AA-guarded `--muted` and `--accent-subtle-foreground` via candidate walk;
  contrast-picked foregrounds; opaque `--overlay`; `--destructive*` omitted when no
  error role; `--font-sans`/`--font-mono` via `fontStack()`.
- `components/generator/use-site-theme.ts` — `"use client"` hook: snapshots
  pre-existing inline values (`value` + `priority`) and restores them exactly;
  diffs applied keys on every re-apply (no stale vars); guarded `matchMedia` with
  scheme-change listener, cleaned up on disable/unmount.
- `components/generator/palette-generator.tsx` — session-only "Apply to site"
  toolbar toggle (`aria-pressed`, `data-testid="apply-to-site-toggle"`), memoized
  light+dark var sets fed to the hook.
- `vitest.setup.ts` — configurable `matchMedia` mock with dispatchable scheme changes.
- Tests: `__tests__/site-theme.test.ts`, `__tests__/use-site-theme.test.tsx`,
  extended `__tests__/palette-generator.test.tsx`.
