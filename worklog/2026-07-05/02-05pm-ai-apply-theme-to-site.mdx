# Task: AI-applied site theme

User request: utilize AI to populate the selected color, font, neutral and status
colors directly to the website for immediate preview. Palette expressed as ramp CSS
variables (`--primary-50…950`, `--neutral-*`, `--success/warning/error-*`, …); AI
populates the current website based on all roles (primary, secondary, tertiary, font,
neutral, status).

Decisions taken in planning:

- This is the "AI-assisted mapping" follow-up explicitly left out of scope by the
  earlier "Apply to site" task (see `01-02pm-apply-tokens-to-site-toggle.mdx`). All
  live-theming plumbing (`lib/site-theme.ts`, `use-site-theme.ts`, `applyToSite`
  toggle) is reused untouched; the new work is the AI layer.
- AI provider: OpenRouter server-side route (same pattern as the deleted
  suggest-colors/generate-preview routes at HEAD), gated by `OPENROUTER_API_KEY`;
  default model bumped to `anthropic/claude-sonnet-4.5`.
- Contract: client sends ramp vars (`themeToCssVars`) + role identities; AI returns
  strict JSON `{light, dark}` of chrome-token → `var(--ramp)` ref or ramp hex; server
  sanitizes to allowlisted tokens with hex-only resolved values (CSS-injection safe),
  client merges over deterministic `siteThemeVars` and auto-enables Apply to site.
- Ramp variables themselves are also applied to `:root` so the site carries the
  user-visible `--primary-50…950`-style block.
- Fonts stay deterministic (`fontStack` of the picked font) — no AI needed there.
- AI mapping invalidates on any palette/typography edit (stale picks).

## Step 2–3 — Codex plan review & enhancement

Codex (read-only `codex exec`) reviewed plan v1 against the codebase and returned
10 findings (6 blockers, 3 improvements, 1 nit). All integrated into plan v2:

1. **Blocker:** `withUniqueSlugs` is private in `lib/color.ts` → export it so client
   role slugs always match the `--<slug>-<shade>` ramp var names sent to the model.
2. **Blocker:** generator also renders on `app/generate/[hex]/page.tsx` → AI props
   must be threaded on BOTH pages (HEAD did this for the old AI features).
3. **Blocker:** in-flight AI responses could apply stale results after palette edits
   → generation counter + AbortController; responses only land if still current.
4. **Blocker:** contrast safety net only covered `*-foreground` pairs → new pure
   post-merge `enforceThemeContrast` also repairs `--foreground`/`--background` and
   `--muted`/`--surface`, applied client-side after AI+deterministic merge.
5. **Blocker:** success/warning status colors never reached the site chrome (only
   error→`--destructive` existed) → add `--success`/`--warning` (+foregrounds) tokens
   to `globals.css` and emit them from `siteThemeVars`; AI allowlist extended.
6. **Blocker:** "no free-text user input" was wrong — role names are user-editable
   and sent to the model → length caps on names/slugs/model, role text treated as
   data in the prompt.
7. Stricter ramp validation: bounded keys (`/^--[a-z0-9-]{1,64}$/`), hex-validated
   values, exact `var(--token)` grammar with no fallback clause.
8. All-empty sanitized AI output → 502, not a fake success.
9. Test-plan gaps folded in: stale-request discard, contrast-repair pairs,
   validation caps, dark-scheme application, both-pages prop threading.
10. Naming aligned with HEAD (`aiDefaultModel`); import wording fixed (named export).
